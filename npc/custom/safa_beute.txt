// ============================================================
//  SafaRO - Beute vergeben, mit Ruecksicht auf Autoloot
// ============================================================
//
//  DAS PROBLEM
//
//  Autoloot wirkt nicht auf alles, was auf dem Boden landet, sondern
//  ausschliesslich auf die Drops des getoeteten Monsters. Die Pruefung
//  steht in mob.cpp:2592, mitten in mob_item_drop - also in der
//  Verteilung der Monster-Drop-Tabelle.
//
//  Was ein Skript mit makeitem hinlegt, geht diesen Weg nie. Es landet
//  ueber map_addflooritem direkt auf dem Boden, und der Spieler muss es
//  aufheben, egal was er eingestellt hat.
//
//  Betroffen war alles, was wir selbst vergeben:
//
//      Safari Trophy        npc/custom/safa_safari.txt
//      Episoden-Materialien npc/custom/safa_episoden.txt
//      MVP Destiny Coins    npc/custom/safa_shops.txt
//
//  DIE LOESUNG
//
//  Wir fragen, ob der Spieler diesen Gegenstand selbsttaetig
//  einsammeln WUERDE. Wenn ja, geben wir ihn direkt - sonst legen wir
//  ihn hin wie bisher. Damit verhaelt sich unsere Beute so, wie der
//  Spieler es von Monster-Drops kennt.
//
//  ERST NUR ZUR HAELFTE GELOEST
//
//  Zuerst stand hier has_autoloot(). Ein Spieler meldete daraufhin:
//  @autoloot wirkt, @alootid und @aloottype nicht.
//
//  Zu Recht. has_autoloot() (script.cpp:27567) liefert ausschliesslich
//  sd->state.autoloot - die Prozentzahl aus @autoloot. Die beiden
//  Listen liegen daneben und werden nicht angesehen:
//
//      sd->state.autoloot       @autoloot,    uint16   pc.hpp:427
//      sd->state.autolootid[]   @alootid,     Liste    pc.hpp:428
//      sd->state.autoloottype   @aloottype,   Bitfeld  pc.hpp:429
//
//  Umgekehrt prueft rAthenas pc_isautolooting (pc.cpp:13148) genau
//  diese beiden Listen und NICHT die Prozentzahl. Keiner von beiden
//  allein beantwortet die Frage.
//
//  Einen Skriptbefehl, der beides zusammenfasst, gibt es nicht -
//  nachgesehen in der BUILDIN_DEF-Liste. Deshalb steht er jetzt in
//  src/custom/script.inc als is_autolooting. ACHTUNG: das ist C++ und
//  braucht einen Neubau. Ohne ihn kennt der Server den Befehl nicht
//  und diese Datei laedt nicht.
//
//  WARUM NICHT IMMER DIREKT GEBEN
//
//  Weil es eine Einstellung ist. Wer Autoloot bewusst aus hat, will
//  entscheiden, was er aufhebt - meist wegen des Gewichts. Ihm etwas
//  in die Tasche zu zwingen waere dieselbe Bevormundung, nur andersherum.
//
//  DAS GEWICHT
//
//  checkweight vor getitem. Ohne die Pruefung schlaegt getitem bei
//  vollem Beutel fehl, und die Beute ist ersatzlos weg - sie liegt ja
//  auch nicht auf dem Boden. Passt sie nicht, faellt sie hin; dann
//  sieht der Spieler wenigstens, dass es etwas gab.
// ============================================================

function	script	F_SafaBeute	{
	.@id = getarg(0);
	.@n  = getarg(1, 1);

	if (is_autolooting(.@id) && checkweight(.@id, .@n)) {
		getitem .@id, .@n;
		return;
	}

	getmapxy(.@map$, .@x, .@y, BL_PC);
	makeitem .@id, .@n, .@map$, .@x, .@y;
	return;
}
